## 2. Run a small completion-effort pilot

This is a descriptive internal usability pilot, not a customer-savings experiment. Use consenting contributors already involved with this synthetic prototype; this document authorizes no outreach. Record actual aliases, prior exposure and consent to retaining anonymous task observations. Do not collect names, contact details, voice/video or sensitive information. Participation and recording a product demo are separate decisions.

Use all twelve existing images, matched by image SHA-256, in both conditions for each participant. The same person sees every case twice, so learning and recognition are unavoidable limitations. Alternate which condition runs first across participant IDs: odd IDs typed first, even IDs assisted first. For the second condition reverse the manifest case order. Record actual order and deviations. Provide one unscored fictional warm-up outside the measured set; never quietly include its timing in results. If only one contributor participates, report one participant and their order.

- **Typed:** show the same label pixels; start from a blank customer form, transcribe only readable identifiers, separately confirm and select Check campaign match. Leave missing/unreadable/conflicting identifiers blank. Do not use samples or extraction.
- **Assisted:** start blank, select that exact image, request suggestions, inspect/correct them, separately confirm and check the match. Include file selection, request wait and edits in elapsed time. Do not use the canned sample buttons. Record `mock` or `ai` for every trial; never pool modes. Mock lookup measures interaction with authored fixture proposals, not AI recognition or AI time savings.

Start timing when the participant can see the image and is told to begin with an empty form; end when the first assessment result is visible. Stop at 120 seconds and retain a timed-out row. Image selection belongs inside the assisted interval. For a displayed `needs_information` result, stop the primary timer there; record whether the requested field is appropriate. Do not invent a missing batch to force completion. Optional clarification follow-up is a separate, explicitly recorded task and never replaces the first result.

A moderator uses a monotonic stopwatch, observes rather than completing the task, and records all attempts. Stop on participant request, browser/server failure, or unplanned provider configuration; record the outcome and reason. No retry replaces a failed or timed-out trial. If a retry is useful, add an `attempt` row and describe it separately. Between trials clear the form/confirmation/result; restart the temporary demo if necessary. Assessment history is not a timing result.

Use the demo launcher for the default mock pilot; its adapters stay mock even if provider configuration exists. A live-AI pilot is a distinct run using the documented opt-in server configuration and an explicitly approved provider account/configuration. It needs recorded model/request settings, served-model provenance and retained failures. This protocol does not trigger such a run or send images. Never describe a mock session as AI-assisted evidence.

### Record and score

Copy the three header-only templates under `evidence/evals/study/` into a new ignored local study directory before collection. `sessions.csv` records one participant/session, mode, code revision, protocol revision, packet audit, environment, ordering and prior exposure. `trials.csv` records every attempted case/condition, image hash, stopwatch duration, outcome, final fields/decision, clarification, edited suggested fields and failures. Use `na` where a measurement does not apply, literal `null` for an observed absent identifier, and leave genuinely unknown observations empty with an explanation in `notes`. Use outcome values `completed`, `timed_out`, `failed` or `withdrawn`; preserve any observed duration in raw rows even when it is excluded from completed-task summaries. Do not enter invented zeros. `adjudication.csv` is only for actual reference disagreements.

Score final model/batch against the adjudicated readable reference, preserving `null` for missing/unreadable/conflicting values. Until adjudication, mark scoring provisional and identify the authored reference version. Keep field error counts, blank-but-readable fields, guessed unreadable fields, unresolved decisions, false-eligible decisions and extraction unavailability separate. A conservative clarification is not automatically an error; record whether it requests the unresolved field. Count each suggested identifier field edited after suggestions once per trial (0–2); typed trials use `na` for this measure. Record actual clarification rounds, including zero when observed.

Report participants, planned/attempted/completed/timed-out/failed trials and unavailable calls for each mode and condition. Show elapsed times only for completed tasks, accompanied by all noncompletion counts. Retain raw attempt rows. Report paired typed/assisted durations only where the same participant/case completed both, plus the number of excluded incomplete pairs and their outcomes. Separate first attempts from retries. Small descriptive medians/ranges and case-level differences are sufficient; make no significance, causal savings or generalization claim from this repeated development pilot. Provider request latency is not human completion effort. Publish no participant aliases/notes without reviewing the record.

## Offline timing report

After collecting actual records, run from the repository root:

```sh
evidence/.venv/bin/python -B -m evidence.evals.study_report --sessions evidence/.local/completion-prep-2026-11-08/sessions.csv --trials evidence/.local/completion-prep-2026-11-08/trials.csv --output evidence/.local/completion-prep-2026-11-08/new-timing-report.json
```

Choose a new report path with an existing parent directory. Exit 0 means inputs were accepted and a report was written; exit 2 means invalid inputs or an unusable/existing output. A header-only run returns `no_observations`, zero recorded attempts and no result summaries. It is a tooling check, never a completed study. Write failures can leave incomplete output; inspect it and choose a new path rather than overwriting a previous record. No credential/provider/payment access occurs.

Use exact CSV headers. Session records require `rajiv-human-evaluation-1`, full protocol/evidence commit hashes, a UTC start timestamp, `consent_recorded: true`, prior exposure/environment details, `typed_first` or `assisted_first`, and `reference_scoring_status: provisional`. The reference version must match the manifest's dataset version. Mock sessions use `provider: fixture` and `requested_model: na`; AI sessions use `omniroute` and record a model plus configuration/served-model provenance paths. Those pointers are self-reported and never opened or verified by this tool. Warm-up omission needs an explanatory note. Input CSVs are limited to 1 MiB each.

Trials bind to a known session/participant alias, case and exact image hash. Record unique global positions within the session and contiguous attempts per case/condition starting at 1. Keep failed first attempts before retries. Completed trials require an observed duration, final identifiers (`null` for an observed absent value) and the displayed `eligible`, `excluded` or `needs_information` decision. Timings must be finite and between zero and one day; any completed task beyond 120 seconds or early/unknown timeout needs a documented deviation. Unknown timing, failures and withdrawals need notes. The tool rejects duplicate/missing attempts, inconsistent mode/identity, malformed CSV and edited scoring columns that contradict its recomputed authored-reference comparisons.

Typed rows set extraction unavailable to `false` and suggested-field edits to `na`. Assisted edits are 0–2 when observed, `na` when not applicable, or blank when unknown. Use lowercase `true`/`false` for observed flags, and follow the blank/`na`/`null` distinctions above. Do not fill in unknown values to pass validation. Clarification judgments/rounds and edit counts remain self-reported; the tool does not establish their accuracy.

The JSON keeps each session separate, exposes first-attempt outcome/time/error denominators, gives retries separate summaries and pairs only the same session/case with both first attempts completed. All other pairs show their missing/failure/timeout state. Reported differences are `typed_seconds - assisted_seconds`, with no savings claim. Unknown availability and omitted pairs remain visible. Declared order is checked against the protocol's manifest-then-reverse prefix; a mismatch is retained as a flag, not discarded. Scoring always uses provisional authored development references from the selected manifest; adjudicated/holdout/validated session claims are not accepted. `--manifest PATH` can select another compatible synthetic development manifest, without establishing independent review.

Reports bind raw session/trial/manifest hashes and the reporter source hash, omit aliases/free-text/path pointers/raw final identifiers, and retain unauthenticated-human-work and development-only flags. They still need review before sharing. The original local CSVs retain every supplied measurement and note. Independent label adjudication and supported holdout reporting remain separate work.
